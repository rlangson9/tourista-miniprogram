2 · Start these 3 long-lead items on Day 1 (in parallel)

These take days or weeks because other people / government review them. Kick them off immediately; everything else can proceed while you wait.

LONGEST — START NOW ① Domain ICP filing (工信部备案) for api.touristaar.com

  • Why: WeChat only allows mini programs to talk to HTTPS domains that have completed ICP filing with a subject matching the mini program's subject.
  • Lead time: ~7–20 working days (the most variable step).
  • Where: via your cloud provider (Alibaba Cloud / Tencent Cloud) — filing requires a mainland-hosted server.
  • Gotcha: the domain registrant, the business licence, and the mini program subject must all match. If touristaar.com is registered under a different name, fix the WHOIS first.

START NOW ② Mini program 备案 (ICP filing for the mini program)

  • Why: Since Sept 2023, every mainland mini program must complete its own 备案 before it can be released.
  • Lead time: platform review ~1–2 working days + provincial communications bureau review ~1–20 working days (typically under 2 weeks).
  • Where: MP console → home page [去备案] (or 设置 → 基本设置). Five steps: fill info → platform review → MIIT SMS verification (within 24h!) → bureau review → done.
  • Gotcha: the SMS verification link expires in 24 hours — do it the same day or you restart.

START EARLY ③ Confirm your service category (服务类目) & qualifications

  • Your mini program sells paid Africa business-study tour packages with deposits via WeChat Pay.
  • WeChat's open-category list puts travel / tours under the 旅游 category, which requires a 《旅行社业务经营许可证》 (Travel Agency Business Licence) matching your subject.
  • Options: (a) obtain/hold the travel licence, (b) re-frame the service under a business-services category if the reviewers accept it — but paid tour bookings are usually treated as travel. Confirm this with WeChat early; it can block review.

4 · Phase 1 — Server, domain & HTTPS

You can do this while the filings in §2 are in progress.

1

Buy a China mainland cloud server

Recommended: Alibaba Cloud ECS or Tencent Cloud CVM. Minimum 1 vCPU / 2 GB RAM / 40 GB SSD (matches your DEPLOYMENT_GUIDE.md). Choose a region near your users (e.g. Shanghai/华东). Mainland server is required for ICP filing.

2

Point DNS: add api.touristaar.com

At your DNS provider, add an A record: api → your server's public IP. Wait for propagation (check with dig api.touristaar.com).

3

Install the stack on the server

# Ubuntu 22.04
sudo apt update && sudo apt install -y nginx git
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
sudo npm install -g pm2
node --version   # must be >= 22.5
4

Deploy the backend

cd /opt
git clone <your-repo-url> tourista-miniprogram   # or scp -r ./tourista-backend user@server:/opt/
cd /opt/tourista-miniprogram/tourista-backend
npm install --production

Then copy and edit the env file — fill in the real credentials (you'll get the WeChat ones in Phase 3/4):

cp .env.example .env
nano .env
5

Start the service with PM2

cd /opt/tourista-miniprogram/tourista-backend
pm2 start src/server.js --name tourista-api
pm2 save && pm2 startup
pm2 status
6

Configure Nginx reverse proxy

sudo nano /etc/nginx/sites-available/tourista-api
server {
    listen 80;
    server_name api.touristaar.com;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_cache_bypass $http_upgrade;
    }
}
sudo ln -s /etc/nginx/sites-available/tourista-api /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
7

Add HTTPS (mandatory for WeChat)

WeChat only accepts HTTPS legal domains. Free option with Let's Encrypt:

sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d api.touristaar.com
sudo certbot renew --dry-run   # test auto-renewal

certbot auto-writes the port-80→443 redirect and SSL config.

8

Verify the backend is live over HTTPS

curl https://api.touristaar.com/health
# expected: {"ok":true,...}
curl https://api.touristaar.com/api/trips   # public endpoint

5 · Phase 2 — ICP filings

These two filings were already introduced in §2 — start them immediately. Summary of where to go:
  • Domain filing: your cloud provider's 备案 console (Aliyun: 备案 / Tencent: 网站备案). Submit the api.touristaar.com record. ~7–20 working days.
  • Mini program filing: WeChat MP console → [去备案]. Follow the 5 steps. After bureau approval you get a 备案号 shown on the mini program page.
Hard requirement: the filing subject (company name) on the domain, the mini program, and the merchant account must be identical. One mismatched character → rejection → re-queue.

6 · Phase 3 — WeChat Mini Program console setup

Console: mp.weixin.qq.com. Do these after the API is HTTPS-reachable (Phase 1).

1

Whitelist server domains

MP console → 开发 → 开发管理 → 开发设置 → 服务器域名. Add:

FieldValue
request 合法域名https://api.touristaar.com
uploadFile 合法域名https://api.touristaar.com
downloadFile 合法域名https://api.touristaar.com

Requirements: HTTPS, no port, domain must be ICP-filed, and you verify ownership with a check file or a validation record. Newly-filed domains can only be added ~24h after filing.

2

Get AppID secret & configure login

MP console → 开发 → 开发管理 → 开发设置 → AppSecret (generate + save it). Put it and the AppID into the backend .env:

WX_APPID=wx69547682e29d99ca
WX_SECRET=your_generated_appsecret
3

Set your service category (服务类目)

MP console → 设置 → 服务类目. Choose categories that match and provide qualifications. For paid tour bookings, the 旅游/旅行社 category requires the 《旅行社业务经营许可证》. Confirm your category strategy from §2③ now — it directly affects whether review passes.

4

Complete the privacy protection guidelines (用户隐私保护指引)

MP console → 设置 → 服务内容声明 → 用户隐私保护指引. Declare exactly what you collect. Your booking form collects name, phone, passport number, company — passport numbers are sensitive personal info, so list them explicitly. If you later ask for 手机号 via getPhoneNumber, declare that too.

Undeclared data collection is a common rejection reason — declare first, collect only what you need.
5

Bind the merchant account & enable JSAPI payment

  1. Merchant console (pay.weixin.qq.com) → 产品中心 → JSAPI支付 → 申请开通 (review ≤ ~7 working days).
  2. 产品中心 → AppID账号管理 / APPID授权 → 关联/添加 the mini program AppID wx69547682e29d99ca → submit.
  3. Mini program console → 功能 → 微信支付 → accept/confirm the binding.
  4. Ensure merchant subject = mini program subject (or a valid authorization).
6

Collect the WeChat Pay API credentials (for code in Phase 4)

Merchant console → 账户中心 → API安全:

  • 申请 API证书 (download cert + note the serial number and private key)
  • 设置 APIv3密钥 (32 chars)
  • Your 商户号 mchid (from 账户中心)
Keep these private — they go into the server's .env, never into the mini program code.

7 · Phase 4 — Finish the remaining code

Only two code tasks remain, plus config. Everything else already works.

1

Point the mini program at the production API

File: app.js, line 5. Change:

baseUrl: 'http://localhost:3000'   →   baseUrl: 'https://api.touristaar.com'
2

Implement WeChat Pay v3 JSAPI in the backend

File: tourista-backend/src/services/wechat.js, function createPaymentOrder() (currently a stub marked TODO). It must:

  1. Call the unified order API: POST https://api.mch.weixin.qq.com/v3/pay/transactions/jsapi with { appid, mchid, description, out_trade_no, notify_url: 'https://api.touristaar.com/api/payment/notify', amount:{ total: totalFen }, payer:{ openid } }.
  2. Sign the request with your merchant private key (RSA-SHA256) using the APIv3 auth scheme (Authorization: WECHATPAY2-SHA256-RSA2048 ...).
  3. Get prepay_id, then build the exact params your pages/booking/booking.js already expects: 
    payParams = {
  timeStamp: String(seconds),
  nonceStr,
  package: 'prepay_id=' + prepayId,
  signType: 'RSA',
  paySign:  // sign of the above with your merchant private key
}

Then finish the notify handler at src/routes/public.js → POST /api/payment/notify (currently just returns the success envelope). It must verify the Wechatpay-Signature header, decrypt resource.ciphertext (AEAD_AES_256_GCM) with your APIv3 key, and call applyPaidToOrder() when trade_state === 'SUCCESS' — the helper already exists in the same file.

Install a helper lib if you like (e.g. wechatpay-node-v3 or tenpay), or hand-roll with Node's crypto. Don't hard-code credentials.

3

Add the Pay credentials to the server .env

WXPAY_MCHID=your_mchid
WXPAY_KEY=your_api_v3_key_32_chars
WXPAY_SERIAL=your_cert_serial_number
WXPAY_PRIVATE_KEY_PATH=/etc/ssl/tourista/apiclient_key.pem

Then pm2 restart tourista-api.

4

(Recommended) Swap placeholder advisor contacts & move catalog data

  • Replace the mock advisor WeChat IDs (TouristaAR_Advisor / TouristaAR_Lead) with your real IDs, or add a 客服消息 (customer-service message) button.
  • Later, move trip data out of utils/data.js into the backend so you can update trips without resubmitting for review.

8 · Phase 5 — Test on the Trial version (体验版)

1

Upload from DevTools

Open the project in WeChat DevTools → click 上传 (Upload) → set version number (e.g. 1.0.0) + release notes.

2

Set the Trial version & invite testers

MP console → 管理 → 版本管理 → 开发版本 → 选为体验版. Add tester WeChat IDs (最多 15 人 for trial).

3

Test on real devices

  • Real-device preview (真机预览) via the trial QR code.
  • Test the full user journey: login → browse trip → booking form → real WeChat Pay deposit (charge a tiny amount, e.g. ¥0.01, then refund) → order status → partner application.
  • Confirm wx.request to https://api.touristaar.com succeeds with the whitelist (domain check no longer blocks).
  • Test on both iOS and Android, plus a low-end device.
Remember project.config.json has "urlCheck": false — that's fine for local dev, but the whitelist in the console is what governs real devices. Don't ship with localhost.

10 · Phase 7 — Release & go live (发布)

1

Release the approved version

MP console → 管理 → 版本管理 → 审核通过 → 发布. You're live! 🎉

2

Post-launch checks (first 24h)

  • Search your mini program by name in WeChat to confirm it's public.
  • Place a real test order end-to-end (payment, order status, admin dashboard).
  • Watch backend logs: pm2 logs tourista-api and WeChat Pay callback logs.
  • Check MP console → 统计 (WeChat Analytics) for crashes / errors.
3

Version management going forward

Every future update also goes through 上传 → 体验版 → 提交审核 → 发布. Plan updates in batches to avoid review friction. Keep at least one previous version rollbackable in 版本管理.

4

Promote

Generate the mini program QR code (MP console → 设置 → 基本设置 → 小程序码) for posters/social. Link it from your official WeChat account and touristaar.com. There's already a QR code.jpg in your repo to reuse.
